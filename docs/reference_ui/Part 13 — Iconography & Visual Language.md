# MASTER UI DESIGN SYSTEM

## Part 13 — Iconography & Visual Language

Version: 1.0

Status:
Official Iconography & Visual Language Specification

---

# PURPOSE

This document defines the visual language of the application.

Every icon.

Every illustration.

Every badge.

Every visual indicator.

Every decorative element.

must follow one unified visual system.

Users should immediately recognize every interface element as belonging to the same application.

---

# DESIGN GOALS

The interface should feel:

Professional

Minimal

Premium

Technical

Modern

Consistent

Elegant

Purposeful

Never playful.

Never childish.

Never cartoonish.

Never resemble mobile applications.

---

# ICON PHILOSOPHY

Icons communicate actions.

Text communicates meaning.

Never replace readable labels with icons alone.

Icons support understanding.

They do not replace it.

---

# ICON STYLE

One icon family only.

Preferred style:

Rounded Outline

Consistent Stroke

Minimal Detail

No filled icons unless absolutely necessary.

Never mix multiple icon packs.

---

# PREFERRED ICON SETS

Preferred

Lucide

Heroicons (Outline)

Phosphor (Regular)

Tabler Icons

Feather

Avoid mixing them.

---

# ICON STROKE

Consistent stroke width.

Recommended

1.75 px – 2 px

Never mix thin and thick icons.

---

# ICON SIZES

Toolbar

20 px

Buttons

18 px

Sidebar

20 px

Timeline

16 px

Menus

18 px

Dialogs

20 px

Status Pills

14 px

Never use arbitrary sizes.

---

# ICON ALIGNMENT

Icons always align to the design grid.

Icon spacing

8 px

Text spacing

8–12 px

Vertical alignment must be visually centered.

# AVATARS

Circular

Minimal

# ILLUSTRATIONS

Empty States

Welcome Screen

Onboarding

Errors

Never use decorative illustrations inside editing workflow.

---

# EMPTY STATE ILLUSTRATIONS

Style

Minimal

Monochrome

Accent Highlights

Low Detail

Soft Gradients

Purpose

Guide users.

Never distract.

---

# ERROR ILLUSTRATIONS

Simple.

Professional.

Minimal.

---

# LOADING INDICATORS

Minimal spinner.

Progress ring.

Progress bar.

Skeleton loading.

Avoid excessive animations.

---

# DIVIDERS

Use subtle separators.

Prefer whitespace over visible lines.

Never create visual clutter.

---

# DECORATIVE ELEMENTS

Decoration exists only when it improves hierarchy.

Never decorate simply to fill empty space.

---

# BRANDING

Brand identity should remain subtle.

Logo appears:

Splash Screen

Top Navigation

About Dialog

Never repeat logos throughout the editor.

---

# LOGO RULES

Simple.

Monochrome preferred.

Readable at small sizes.

Never oversized.

# GLYPHS

Use glyphs only when universally understood.

---

# EMOJIS

Never use emojis inside production UI.

Exception

Internal Notes

Prototype only.

---

# ANIMATED ICONS

Allowed only for:

Loading

Processing

Rendering

AI Thinking

Never animate static toolbar icons.

---

# ACCESSIBILITY

Icons must never be the only source of information.

Every icon should have:

Tooltip

Accessible label

Keyboard support

---

# CONSISTENCY CHECK

Before adding any new icon ask:

Does this icon already exist elsewhere?

Does it match the current icon family?

Does it use the same stroke?

Does it use the same size?

Does it use the same spacing?

If not,

replace it.

---

# IMPLEMENTATION RULES

Never introduce multiple icon libraries.

Never mix filled and outline styles.

Never use bitmap icons.

Prefer scalable vector graphics.

Always align icons to the spacing grid.

Maintain consistency across the application.

---

# FINAL PRINCIPLE

Icons should quietly support the interface.

Users should understand actions immediately without visual confusion.

The application should feel like one cohesive professional desktop product—not a collection of unrelated widgets.
